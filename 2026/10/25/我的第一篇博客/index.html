我是怎么搭建这个博客的

发表于2026-10-25|更新于2026-10-25|技术笔记
|总字数:1.3k|阅读时长:4分钟

起因

想找个地方把平时折腾的东西记下来。

用别人的平台总觉得不踏实：排版不由自己，哪天平台改版或者关停，写的东西说没就没。所以从一开始就定了两个要求：内容必须是纯文本存在自己手里，网站得是自己的域名。

最后选的路子是 Hexo 写、GitHub 存、Cloudflare 发布。

一、选型

静态博客生成器不少，Jekyll、Hugo、Hexo 都能干这事。选 Hexo 的原因很朴素：它用 Node.js，我电脑上本来就有；配置文件是 YAML，看得懂；中文资料多，出问题好搜。

主题选了 Butterfly，功能齐全，文档写得清楚，配色也好改——我把主色调成了头像上那片蓝。

五、Cloudflare Pages 接管

GitHub Pages 在国内访问时快时慢，而且自带域名不好看。所以把它交给 Cloudflare Pages：

  1. Cloudflare 控制台 → Workers 和 Pages → 创建 → 连接到 Git
  2. 授权 GitHub，选中 zhxinyu1.github.io 这个仓库
  3. 框架预设选「无」，构建命令留空（因为推上去的已经是成品 HTML）
  4. 部署

之后每次 hexo d 推上去，Cloudflare 都会监听到新提交，自动拉取、重新部署。控制台里会多出一条部署记录，这是正常机制，不是配置被改了。

六、绑定自己的域名

找到自己心仪的域名进行绑定。

在 Cloudflare 的 DNS 里加两条记录，类型都是 CNAME，全部开启橙色云代理，TTL 自动：
| CNAME | @ | zhxinyu1-github-io.pages.dev |
| CNAME | www | zhxinyu1-github-io.pages.dev |

第二条是为了解决访问 www 子域名时跳广告的问题。

DNS 生效要等 2 到 10 分钟。测试时用无痕窗口加 Ctrl+F5，避开浏览器缓存。

七、踩过的几个坑

1. 一篇不写，首页就 404

Hexo 的首页生成器在 per_page > 0 时，如果文章数为 0，分页循环一次都不跑，首页根本不会生成，访问根路径直接 404。

解决办法是写一个兜底生成器 scripts/empty-site.js：检测到一篇文章都没有时，用 perPage: 0 补出首页；有文章了就返回空数组，让位给官方生成器，不影响正常分页。

2. 搜索不工作

hexo-generator-searchdb 生成的搜索索引，文件名必须以 .xml 结尾，主题的搜索脚本才按 XML 解析：

写成 .json 或者别的名字，搜索框就是永远转圈圈。

3. 更新了看不到新内容

先排浏览器缓存（无痕窗口 + Ctrl+F5），再排 Cloudflare 的 CDN 缓存（控制台 → 缓存 → 清除缓存）。九成情况是前者。

4. 访问量统计

一开始用不蒜子做访客数和浏览量，后来觉得没必要，自己的小站不需要靠数字撑场面，就把三项全关了。关掉之后主题模板里的那段脚本不再输出，页面反而更干净。

八、现在的工作流

日常就三件事：

  1. npx hexo new "标题" 新建文章
  2. 用编辑器打开 source/_posts/标题.md 写完，npx hexo s 本地看一眼效果
  3. 双击 push.bat：清理、生成、部署

1 到 2 分钟后线上就是新的了。

最后

整套东西搭下来，最有价值的部分不是学会了几个命令，而是想明白了一件事：内容要攥在自己手里。

Markdown 就是纯文本，扔进任何一个编辑器都能读；仓库是自己的，域名是自己的，换个平台、换个静态生成器，文章一个字都不用改。

技术会过时，但这个原则不会。

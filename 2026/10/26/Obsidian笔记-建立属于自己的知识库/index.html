Obsidian 笔记：建立属于自己的知识库

发表于2026-10-26|更新于2026-10-27|技术笔记
|总字数:2k|阅读时长:6分钟

最近了解到 Obsidian（以下简称 OB）这款软件，发现它非常适合配合 AI 搭建个人知识库。之前我一直用系统自带的笔记本写笔记，但用久了觉得功能太单一，缺乏结构化的知识管理能力，于是决定尝试一下这个新工具。

一、Obsidian 基础使用：为什么它是知识库神器？

刚上手 Obsidian，我就被它的几个核心功能惊艳到了：

  • 本地 Markdown 笔记：所有笔记都是本地的 .md 文件，不依赖任何云端数据库，数据完全掌握在自己手里。而且 Markdown 格式非常适合普通大模型问答，也极度契合 Agent 自动读写文件的需求。
  • 双向链接：这是 Obsidian 的灵魂。通过 [[笔记名]] 就能在笔记之间建立链接，点击即可跳转。随着笔记越来越多，这些链接会自动形成一张「知识关系图谱」，让零散的知识点产生化学反应。
  • 标签（Tags）：使用 #标签名 可以快速对笔记进行分类和检索，配合双链使用，管理效率翻倍。
  • Canvas 画布：这是一个无限大的白板，可以把笔记、图片、网页链接随意拖拽、连线，非常适合做头脑风暴或梳理复杂的项目逻辑。

这些特性让 Obsidian 不仅仅是一个笔记软件，更是一个能伴随你成长的「第二大脑」。

二、Obsidian 的云同步

Obsidian 的「本地优先」哲学是它的魅力，但同时也带来了一定弊端：它没有免费的官方同步服务。官方提供的 Obsidian Sync 每月需要 5 美元，对于国内用户来说不仅价格偏高，还面临海外服务器延迟的问题。

在网上搜了一圈，最火的免费方案就是 Remotely Save 插件 + 坚果云 WebDAV。

  1. 登录坚果云网页端，在「账户安全」里生成了一个第三方应用密码。
  2. 在 Obsidian 安装 Remotely Save 插件，填入坚果云的 WebDAV 地址、邮箱和应用密码。
  3. 点击「检查连接」，提示成功，开始同步。

但是，在实际使用中坚果云频繁报 503 错误，甚至直接限流。后来了解到，坚果云对 WebDAV 的 API 请求频率有严格限制，并不适合做高频的云同步首选。

在 WebDAV 方案受挫后，我想到了以前建立博客时用到的 Git 上传方案。经过一番研究与查阅资料，发现它完全可行。

它有两个入口：电脑端用 Obsidian 的 Git 插件，手机端用 Termux（见下一节），两边共用同一个 GitHub 仓库。

1. 安装插件

在 Obsidian 的第三方插件市场中搜索并安装 Obsidian Git 插件，然后启用。

2. 插件配置

打开插件设置页面，我逐项检查了一遍，最终决定所有参数保持默认不动。事实证明，默认配置已经足够好用，过度自定义反而容易引发各种奇怪的问题。

3. 电脑端一键同步

按 Ctrl+P 调出命令面板，输入 Obsidian Git: Commit and sync，回车即可一键完成本地提交并推送到 GitHub 远程仓库。

三、手机端操纵方法

Android 上的 Obsidian 没有现成的 Git 插件可用，得借 Termux 这个终端环境来操作。好处是脚本化之后，一次点击和插件没什么区别。

1. 前期准备

  • 手机安装 Termux（建议从 F-Droid 装，Play 商店上的版本已经停止更新）
  • GitHub 上新建一个仓库专门存放 Obsidian 笔记库
  • 本地电脑已经配置好 SSH 密钥；手机 Termux 同样配置一份，实现免密码推送到 GitHub
  • 仓库设为私有，笔记里难免有私人内容，公开等于摊开给人看

8. 同步规则与避坑

  1. 开写之前先拉一次。手机和电脑轮流用的时候，先同步再动手，能最大程度避免冲突。
  2. 两边别同时改同一个文件。这是最容易撞上 Git 冲突的场景，一旦发生就得手工处理 <<<<<<< 标记。
  3. 仓库记得设为私有。笔记里难免有私人内容，公开仓库等于摊开给人看。
  4. 脚本里先提交再拉取。原始写法是先 pull 再 commit，本地还有未提交改动时 pull 会直接报错；现在先把本地改动落成一个 commit，再 pull --rebase 把远程新提交垫在下面，冲突面小得多。

经过反复测验，该方案不仅同步稳定，而且完美避开了 WebDAV 的限流痛点，目前已成为我日常使用的主力同步方式。

四、个人总结：工具为辅，记录为主

折腾了一圈同步方案，我最大的感触是：Obsidian 和 Git 终究只是辅助工具，真正重要的永远是日常的记录与思考。

我们很容易陷入「折腾工具」的陷阱：为了找一个完美的同步插件耗费半天，为了美化界面安装几十个主题，或者为了构建一个看似完美的知识图谱而焦虑。但工具再强大，如果里面没有扎实的内容，也只是一个空壳。把省下来的时间用来多写几篇笔记、多记录一些日常的灵感与反思，才是建立个人知识库的真正意义。

毕竟，笔记的价值不在于它存放在哪里、用什么软件打开，而在于那些文字是否真正沉淀成了你自己的认知。
